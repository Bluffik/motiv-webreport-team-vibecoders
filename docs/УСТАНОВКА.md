# Установка и эксплуатация

Документ для тех, кто ставит и сопровождает «Веб отчётность». Значения в «Паспорте стенда» заполняются при установке. Пароли сюда не пишутся: они лежат в `.env` на сервере, а при установке по SSH — ещё в `deploy/servers.env` и `deploy/.secrets` на машине, с которой ставили. В git эти файлы не попадают.

## Паспорт стенда

| Параметр | Значение |
|---|---|
| Адрес приложения | `‹APP_URL›` |
| Сервер | `‹APP_HOST›`, ОС `‹APP_OS›`, каталог `/opt/webreport` |
| Домен | `‹APP_DOMAIN›` → `‹APP_HOST›` |
| Почтовый сервер | `‹SMTP_HOST›:‹SMTP_PORT›`, `‹SMTP_SECURITY›`, отправитель `‹SMTP_FROM_ADDRESS›` |
| Разрешённые домены получателей | `‹MAIL_ALLOWED_DOMAINS›` |
| Версия | `‹VERSION›`, установлена `‹INSTALL_DATE›` |
| Вход администратора | `admin`, пароль — в `.env` на сервере (`ADMIN_PASSWORD`) |
| Демо-пользователи | `duty/duty`, `engineer/engineer` (только при `SEED_DEMO=true`) |
| Сертификат | `‹CERT›` (Let's Encrypt, корпоративный или самоподписанный) |
| Резервные копии | каждую ночь в 03:00, `/opt/webreport/backups`, хранятся 30 последних |

## Как устроено

```
Рабочие места (Chrome 75+)
        │ HTTPS 443 (HTTP 80 → перенаправление)
        ▼
┌──────────────────── сервер ────────────────────┐
│  webreport-app (Node.js 24)  ──►  webreport-db (MariaDB) │
│  внутренняя сеть Docker, порт 3306 наружу закрыт         │
└────────┬───────────────────────────────────────┘
         │ SMTP по логину и паролю
         ▼
  почтовый сервер компании ──► внутренние адреса
```

- Приложение и база работают в Docker Compose (v1 или v2).
- Письма уходят через почтовый сервер компании: приложение входит на него как обычный почтовый клиент. Получатели — только адреса разрешённых доменов.

## Что нужно

| Что | Зачем |
|---|---|
| Linux-сервер (Debian 12 / Ubuntu 22+), 2 ядра, 2–4 ГБ, 20 ГБ на базу и резервные копии | приложение и база |
| Docker и docker-compose любой версии | контейнеры |
| Порт для HTTP/HTTPS (по умолчанию 80 и 443; меняются в `.env`) | доступ пользователей |
| Комплект `webreport-<версия>.tar.gz` | образы приложения и MariaDB — Docker Hub на сервере не нужен |
| SMTP: адрес, порт, логин, пароль, адрес отправителя | уведомления |
| Домен и сертификат (необязательно) | HTTPS без предупреждений браузера |

## Комплект поставки

- Готовый архив выкладывается в GitHub Releases по тегу `v<версия>`.
- Собрать самостоятельно можно на машине с Docker и интернетом:
  ```bash
  sh deploy/build-bundle.sh ‹VERSION›     # → dist-bundle/webreport-‹VERSION›.tar.gz
  ```

## Установка

```bash
mkdir -p /opt/webreport
tar xzf webreport-‹VERSION›.tar.gz -C /opt/webreport --strip-components=1
cd /opt/webreport
sh deploy/install.sh                     # демо-стенд: SEED_DEMO=true APP_URL=https://‹APP_DOMAIN› sh deploy/install.sh
```

`install.sh`:
- загружает образы из архива;
- при первом запуске создаёт `.env` со случайными паролями;
- поднимает контейнеры и ждёт готовности;
- выводит адрес и пароль администратора.

Если docker-compose на сервере другой версии, `deploy/compose.sh` сам выберет `docker-compose` или `docker compose`. Compose-файлы — в формате 2.4 и читаются обеими версиями.

### HTTPS

Два варианта:
- **Сертификат в приложении.** Положите `certs/server.crt` и `certs/server.key` и выполните `sh deploy/compose.sh up -d --no-build`. Приложение будет слушать 443, перенаправлять HTTP на HTTPS, включит HSTS и cookie с флагом `Secure`. Подойдут:
  - корпоративный сертификат;
  - Let's Encrypt:
    ```bash
    certbot certonly --standalone -d ‹APP_DOMAIN› --agree-tos -m ‹LE_EMAIL› \
      --pre-hook 'docker stop webreport-app || true' --post-hook 'docker start webreport-app || true' \
      --deploy-hook 'cp /etc/letsencrypt/live/‹APP_DOMAIN›/fullchain.pem /opt/webreport/certs/server.crt; cp /etc/letsencrypt/live/‹APP_DOMAIN›/privkey.pem /opt/webreport/certs/server.key'
    ```
  - самоподписанный: `sh deploy/make-cert.sh ‹имя-или-IP›`.
- **TLS на балансировщике.** В `.env`: `TRUST_PROXY=<адрес балансировщика>` и `COOKIE_SECURE=true`.

### Почта

Войдите под `admin` и откройте «Администрирование → Уведомления → Почтовый сервер»:
1. Укажите адрес и порт сервера, шифрование, логин, пароль, адрес отправителя, разрешённые домены получателей.
2. «Проверить и отправить» — на внутренний адрес.
3. «Сохранить».
4. «Ссылки в письмах ведут на» — `https://‹APP_DOMAIN›`.
5. В правилах уведомлений укажите настоящие внутренние адреса.

### Установка по SSH одной командой

С машины, где лежит проект (Git Bash, Linux или macOS: нужны ssh, scp, tar, curl, node):

```bash
cp deploy/servers.env.example deploy/servers.env   # заполнить
sh deploy/remote-deploy.sh check                   # доступ, ОС, Docker, место, DNS
sh deploy/remote-deploy.sh all                     # docker → bundle → app → configure → status
```

## Проверка после установки

- [ ] Сайт открывается по HTTPS, `http://` перенаправляет на `https://`.
- [ ] Вход `admin`, пароль администратора сменён.
- [ ] Проверочное письмо пришло на внутренний адрес.
- [ ] На вкладке «Аварии» есть форма и табло, в «Инвентаре БС» — объекты.
- [ ] `nmap ‹APP_HOST› -p 3306` — порт закрыт.
- [ ] Часы синхронизированы: `timedatectl` → `System clock synchronized: yes`.
- [ ] `sh deploy/compose.sh ps` — оба контейнера `healthy`.

## Обновление

```bash
tar xzf webreport-‹NEW›.tar.gz -C /opt/webreport --strip-components=1
cd /opt/webreport && sh deploy/install.sh
```

`.env`, сертификаты, резервные копии и данные базы (том `db-data`) сохраняются. Схема базы обновляется сама при запуске.

## Резервные копии

- Каждую ночь — через cron: `0 3 * * * cd /opt/webreport && sh deploy/backup.sh`.
- Вручную: `sh deploy/backup.sh` → `backups/webreport-ДАТА.sql.gz`, хранятся 30 последних.
- Восстановление: `sh deploy/backup.sh restore backups/webreport-ДАТА.sql.gz`.
- Копии стоит забирать и на другой сервер.

## Если что-то не так

| Признак | Что проверить |
|---|---|
| Сайт не открывается | `sh deploy/compose.sh ps`, `sh deploy/compose.sh logs --tail=100 app`, открыт ли порт на сервере |
| Сертификат не выпускается | A-запись домена указывает на сервер, порт 80 открыт и свободен |
| Письма не уходят | «Уведомления → Журнал»: текст ошибки на русском; «Проверить подключение» в настройках почты |
| «Адреса вне компании не допускаются» | адрес не из разрешённых доменов — добавьте домен в настройках почты или исправьте правило |
| После смены `JWT_SECRET` пароль почты «не расшифровать» | введите пароль почты заново |
| Время аварий сдвинуто | `APP_TZ=Asia/Yekaterinburg` в `.env`, часы сервера синхронизированы |
